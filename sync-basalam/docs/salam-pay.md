# سلام‌پی در ووسلام

نسخه 1.10.32 درگاه فروشگاه سلام‌پی را داخل `includes/SalamPay` ارائه می‌کند. این درگاه برای پرداخت سفارش مشتری است؛ کد شارژ اعتبار و اشتراک در پروژه `integration-gateway` تغییری نکرده است.

## راه‌اندازی

1. بسته ووسلام را نصب یا به‌روزرسانی کنید.
2. در «ووکامرس ← پیکربندی ← پرداخت‌ها ← سلام‌پی» کلید اتصال فروشنده را وارد و درگاه را فعال کنید. لینک «تنظیمات سلام‌پی» در فهرست افزونه‌ها نیز مستقیم همین صفحه را باز می‌کند.
3. عنوان و توضیح، وضعیت پس از موفقیت یا شکست قطعی، نوار معرفی و نشان محصولات را تنظیم کنید. وضعیت موفق پیش‌فرض از قواعد ووکامرس، از جمله سفارش مجازی، پیروی می‌کند. بازگشت خودکار وجه هنگام لغو سفارش تنظیم جداگانه و پیش‌فرض خاموش دارد.
4. اگر افزونه مستقل سلام‌پی فعال است، آن را **غیرفعال** کنید. آن را **حذف نکنید**: حذف‌کننده موجود در فایل ارسالی، گزینه مشترک `woocommerce_salampay_settings` را پاک می‌کند. تا وقتی نسخه مستقل فعال است، ووسلام هیچ درگاه، callback یا عملیات مالی تکراری ثبت نمی‌کند.
5. پیش از استفاده واقعی، پرداخت و بازگشت وجه را با کلید فروشنده روی دامنه تأییدشده و در شرایط مورد تأیید سلام‌پی بررسی کنید. در این تغییر تراکنش واقعی انجام نشده است.

`salampay`، گزینه `woocommerce_salampay_settings`، متادیتای قدیمی `_salampay_*` و مسیر `/wp-json/salampay/v1/callback` حفظ شده‌اند. سفارش‌ها از CRUD ووکامرس استفاده می‌کنند و به جداول posts وابسته نیستند. هیچ کلید پیش‌فرض یا کلید واقعی در کد و خروجی مرورگر وجود ندارد. بروزرسانی از کانال ووسلام انجام می‌شود؛ updater مستقل فایل ارسالی وارد این ماژول نشده است.

## قرارداد و تأیید پرداخت

زیرمجموعه قرارداد رسمی در [contracts/salam-pay.openapi.json](contracts/salam-pay.openapi.json) قرار دارد و در 2026-10-19 از [OpenAPI سلام‌پی](https://salam-pay-api.basalam.com/openapi.json) دریافت شده است. فقط فرم `exclusiveMinimum` عددی خروجی بالادست برای سازگاری OpenAPI 3.0 به `minimum` و `exclusiveMinimum: true` تبدیل شده و هدر احراز هویت مستند در افزونه ارسالی اضافه شده است.

| عملیات | روش و مسیر |
| --- | --- |
| ساخت نشست | `POST /public-api/v1/sessions` |
| استعلام پرداخت | `GET /public-api/v1/payments/references/{reference_id}` |
| ثبت استرداد | `POST /public-api/v1/refunds` |
| استعلام استرداد | `GET /public-api/v1/refunds/{reference_id}/status` |

تمام درخواست‌ها با `X-Client-Secret`، TLS و بدون دنبال‌کردن redirect ارسال می‌شوند. callback، مبلغ یا وضعیت ارسالی مرورگر را مبنای پرداخت نمی‌گیرد. کلید سفارش و روش پرداخت بررسی می‌شوند؛ سپس شناسه مرجع، مبلغ ریالی، واحد پول و شناسه نشست با نتیجه استعلام تطبیق می‌یابند. موفقیت عددی `3` از افزونه ارسالی حفظ شده است. قرارداد بالادست برای `EnumResponse.name` مقادیر مجاز منتشر نکرده است؛ نام‌های شناخته‌شده `FAILED/CANCELLED/CANCELED/EXPIRED` فقط شکست قطعی را تشخیص می‌دهند و وضعیت ناشناخته در انتظار بررسی می‌ماند. تأیید نگاشت وضعیت‌ها در تست پذیرش واقعی لازم است.

واحدهای `IRR`، `IRT/TOMAN`، `IRHR` و `IRHT` پشتیبانی می‌شوند. مبالغ منفی، واحد ناشناخته، تعداد غیرصحیح و مبلغ کمتر یا مساوی ۱۰۰۰ ریال پذیرفته نمی‌شوند. اقلام از قیمت پیش از تخفیف ساخته می‌شوند و اختلاف گردکردن، مالیات و ارسال با مبلغ سفارش تطبیق داده می‌شود؛ تخفیف دوباره اعمال نمی‌شود.

قفل پایگاه داده، ایجاد نشست، تأیید و استرداد یک سفارش را سری می‌کند. مراجعه دوباره به پرداخت از نشست معتبر همان سفارش استفاده می‌کند. پس از timeout، خطای 5xx یا پاسخ نامعتبر، درخواست مالی POST تکرار نمی‌شود و فقط استعلام ادامه می‌یابد. نشست منقضی، تغییر مبلغ و پرداخت دیررس سفارش لغوشده نیاز به بررسی دارند. callback تکراری، سفارش تکمیل‌شده یا مستردشده را دوباره باز نمی‌کند.

## استرداد غیرهمزمان

در دکمه بازگشت وجه ووکامرس، درخواست کامل یا جزئی را ثبت کنید. پیام «درخواست ثبت شد و در انتظار تأیید است» یعنی درخواست به صف پیگیری رفته است. API بالادست قرارداد مشخصی برای بدنه پاسخ ثبت استرداد منتشر نمی‌کند، بنابراین پذیرش درخواست از روی `status_url` یا یک بدنه ساختگی به معنی موفقیت نهایی فرض نمی‌شود.

برای جلوگیری از ثبت بازگشت وجه قطعی پیش از تسویه، `process_refund` در حالت انتظار پیام `WP_Error` می‌دهد؛ ووکامرس آن را در اعلان خود نمایش می‌دهد و رکورد موقت را حذف می‌کند. اطلاعات مبلغ، اقلام، مالیات، درخواست بازگردانی موجودی و کاربر درخواست‌کننده در سابقه مستقل سفارش حفظ می‌شوند. فقط پس از استعلام موفق، تطبیق مبلغ و شناسه‌های پرداخت/استرداد، رکورد واقعی ووکامرس ساخته می‌شود. تمام جزئیات در یادداشت‌ها و بخش بازگشت وجه سلام‌پی سفارش قابل مشاهده است. تا وقتی یک درخواست باز است، استرداد دیگری پذیرفته نمی‌شود. مجموع استرداد نمی‌تواند از مبلغ پرداخت اولیه و مانده سفارش بیشتر شود.

پیگیری هر ۱۵ دقیقه، حداکثر ۹۶ بار انجام می‌شود؛ نخستین بررسی یک دقیقه بعد است. اسکن بازیابی ساعتی به صورت دسته‌های ۵۰ سفارشی، عملیات قطع‌شده و سوابق نسخه مستقل را دوباره به صف بررسی می‌برد. WP-Cron باید اجرا شود؛ در فروشگاه کم‌ترافیک cron واقعی سرور لازم است. برای بررسی فوری از عملیات «بررسی پرداخت و بازگشت وجه سلام‌پی» روی سفارش استفاده کنید. پس از پایان تعداد تلاش‌ها، پیگیری دستی همچنان ممکن است. حذف یا غیرفعال‌سازی ووسلام، سابقه مالی سفارش را پاک نمی‌کند.

در استردادهای نسخه مستقل، ممکن است قبلاً رکورد قطعی ووکامرس با وجود معلق بودن پرداخت ایجاد شده باشد. آن رکورد دوباره ساخته نمی‌شود؛ نتیجه واقعی با استعلام پیگیری می‌شود. تغییر دستی مبلغ یا استرداد دستی همزمان ممکن است ثبت محلی نتیجه تسویه را نیازمند بررسی کند؛ در این حالت وضعیت «تأییدشده؛ نیازمند ثبت در سفارش» نشان داده می‌شود.

## تست محلی

Mock از قرارداد دریافت‌شده ساخته شده است؛ جست‌وجوی mock تیم مالک به دلیل نبود ورود Postman انجام نشد. جست‌وجوی Orbit در این محیط timeout شد. هیچ منبع مشترکی در Postman منتشر نشده است. کنترل‌های `/__control` و `/__state` فقط ابزار fixture محلی‌اند و جزو API ارائه‌دهنده نیستند.

```sh
postman spec lint docs/contracts/salam-pay.openapi.json --issueType syntax --no-report-events
postman simulation run postman/simulations/salam-pay.sim.yaml --port 4900 --no-history --output ndjson
# در ترمینال دیگر؛ کانتینر محلی موجود با PHP 8.2 و WooCommerce:
docker exec -w /var/www/html/wp-content/plugins/sync-basalam basalam-wordpress-local-wordpress-1 php tests/SalamPay/integration.php
docker exec -w /var/www/html/wp-content/plugins/sync-basalam basalam-wordpress-local-wordpress-1 php tests/SalamPay/registration.php normal
docker exec -w /var/www/html/wp-content/plugins/sync-basalam basalam-wordpress-local-wordpress-1 php tests/SalamPay/registration.php standalone
docker exec -w /var/www/html/wp-content/plugins/sync-basalam basalam-wordpress-local-wordpress-1 php tests/SalamPay/registration.php force-update
```

برای محیط دیگر متغیرهای `WORDPRESS_BOOTSTRAP` و `SALAMPAY_TEST_API_URL` را تنظیم کنید. override API فقط با `WP_ENVIRONMENT_TYPE=local` فعال می‌شود. تست اصلی از HTTP واقعی وردپرس، سفارش و موجودی واقعی ووکامرس و HPOS استفاده می‌کند؛ تمام سفارش‌ها و محصولات fixture پاک و تنظیمات اولیه در `finally` بازیابی می‌شوند. درخواست‌های خارجی و ارسال ایمیل هنگام تست مسدودند. گزارش Postman ممکن است کلید سفارش یا کلید نمونه داشته باشد؛ آن را در Git ثبت نکنید.

کد و assets نمایشی از `salampay-plugin` نسخه 0.3.1 ارسالی کاربر، با مجوز GPL-2.0-or-later اقتباس شده‌اند. پیاده‌سازی مالی، استعلام، سازگاری ووسلام و تست‌ها در این ماژول بازنویسی شده‌اند.
